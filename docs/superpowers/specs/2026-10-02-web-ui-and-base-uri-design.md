# Web UI and Real Base URI — Design Spec

Date: 2026-10-02. Extends `2026-10-02-football-lod-design.md`.

## 1. Goals

1. Replace the placeholder namespace `https://example.org/football/` with a real one the owner controls.
2. Add a web application that lets people who do not know SPARQL explore the data, lets people who do know SPARQL query it, and serves every resource URI as Linked Data (HTML for browsers, RDF for machines).

Success criteria:
- No `example.org` remains in `src/`, `ontology/`, `shapes/`, `queries/`, `config.json` or the tests; data, links and the endpoint are rebuilt under the new namespace and every existing check still passes.
- `GET /resource/<kind>/<id>` answers `303 See Other` to an HTML page for browsers and to an RDF document for clients asking for Turtle, JSON-LD, RDF/XML or N-Triples.
- The playground runs the nine existing competency queries and arbitrary read-only SPARQL, and shows results in a table.
- Entity pages for players and clubs show their data, their links to Wikidata/DBpedia/GeoNames, and related transfers, valuations or squad.

Out of scope: dashboard/statistics page, authentication, rate limiting and a public deployment, publishing a static snapshot to GitHub Pages.

## 2. Base URI

- Ontology namespace: `https://vdhugn.github.io/Football-LOD/ontology#`; ontology IRI `https://vdhugn.github.io/Football-LOD/ontology`.
- Resource namespace: `https://vdhugn.github.io/Football-LOD/resource/` (for example `.../resource/player/28003`).
- SHACL shapes namespace: `https://vdhugn.github.io/Football-LOD/shapes#`.
- GitHub Pages only serves static files, so opening these URIs at github.io does not return data by itself. The web app serves exactly the same path structure (`/resource/...`, `/ontology`), so the URIs resolve as soon as the app is reachable under that namespace (own domain, w3id.org redirect or reverse proxy). Locally the app is at `http://localhost:8000` and maps `/resource/<kind>/<id>` to the canonical URI stored in the endpoint. The base URI stays configurable in `config.json`.
- Data, links and endpoint are regenerated by the normal pipeline (`build_rdf`, `link_wikidata`, `load.sh`); Wikidata results are cached by Transfermarkt ID, so relinking is offline.

## 3. Web application

Python 3.12, Flask, Jinja2 templates, plain JavaScript, CodeMirror 5 loaded from cdnjs (needs network while viewing). Package `src/footballweb/`. It talks to Fuseki's query endpoint only (Fuseki runs without `--update`).

### 3.1 Routes

| Route | Behaviour |
|---|---|
| `/` | Search box, links to playground and ontology, the example queries. |
| `/search?q=` | Case-insensitive substring match on `rdfs:label` of Player, Club, NationalTeam, Competition and Country; at most 25 results; query shorter than 2 or longer than 80 characters is rejected with a message. |
| `/resource/<kind>/<id>` | `404` if the resource has no triples. Otherwise `303` with `Location` chosen from the `Accept` header: HTML (default, also `*/*`) → `/page/<kind>/<id>`; `text/turtle`, `application/ld+json`, `application/rdf+xml`, `application/n-triples` → `/data/<kind>/<id>.<ext>`. |
| `/page/<kind>/<id>` | HTML entity page. |
| `/data/<kind>/<name>.<ext>` | `ext` in `ttl`, `jsonld`, `rdf`, `nt`; the outgoing triples of the resource, serialized by rdflib. `404` for unknown resources or extensions. |
| `/ontology`, `/ontology.<ext>` | The ontology: HTML listing of classes and properties for browsers, RDF serialization (`200`, with `Content-Location`) otherwise. Read from `ontology/football.ttl`. |
| `/query` | Playground page. |
| `/api/query` (POST JSON `{"query": "..."}`) | Runs a read-only query through the proxy; JSON response described below. |
| `/api/examples` | The `queries/q*.rq` files as `[{"name", "query"}]`. |

`kind` must match `^[a-z][a-z-]*$`; anything else is `404`. The canonical URI is built exactly like the pipeline does (`Uris.res`), so IDs with special characters round-trip.

### 3.2 Entity page

- Title from `rdfs:label` (falls back to the URI), class names from `rdf:type`, the canonical URI shown as text.
- A table of outgoing properties grouped by predicate; URIs inside the resource namespace become internal links (using the label of the target when it exists), literals are shown with their datatype or language.
- A separate "Linked data" block for `owl:sameAs`, `skos:closeMatch`, `rdfs:seeAlso` and `foaf:depiction` values, as external links; a depiction URL is also shown as an image.
- Player pages add: transfers (date, from, to, fee, newest first, at most 50), market value history (newest first, at most 100) and totals of appearances and goals.
- Club pages add: current squad ordered by market value (at most 60).
- Links to the same resource as Turtle, JSON-LD, RDF/XML and N-Triples.

### 3.3 Playground

- CodeMirror editor with SPARQL highlighting, a drop-down of the nine example queries, Run button (Ctrl+Enter), result table, "Download CSV" and "Download JSON" for SELECT results, Turtle text for CONSTRUCT/DESCRIBE, true/false for ASK.
- The server accepts only SELECT, ASK, CONSTRUCT and DESCRIBE. Queries containing update verbs (INSERT, DELETE, LOAD, CLEAR, DROP, CREATE, COPY, MOVE, ADD) as keywords outside strings are rejected with HTTP 400; anything else Fuseki rejects is returned as HTTP 400 with its message.
- SELECT results are truncated to 1000 rows with a `truncated: true` flag; every Fuseki call has a 60-second timeout.
- JSON response shapes: SELECT `{"form":"select","vars":[...],"rows":[{var:value,...}],"truncated":bool}`; ASK `{"form":"ask","boolean":bool}`; CONSTRUCT/DESCRIBE `{"form":"graph","turtle":"..."}`; errors `{"error":"..."}`.

### 3.4 Configuration and running

- `FUSEKI_URL` environment variable (default `http://localhost:3030/football`); base URIs from `config.json`.
- `make web` runs the app on port 8000 for local use. `docker-compose.yml` gets a `web` service (gunicorn, port 8000) next to Fuseki.

## 4. Error handling

- Fuseki unreachable or erroring on an entity route: HTTP 502 page that says the SPARQL endpoint could not be reached; on `/api/query`: JSON error.
- Unknown resource: 404 page. Bad input to search or API: 400 with a message. No stack traces are shown.
- All user-supplied text placed into SPARQL goes through one escaping function; resource URIs are built only from validated `kind` and escaped IDs.

## 5. Testing

- pytest with the Flask test client and an injected fake Fuseki client; tests cover routing and 303 negotiation, each RDF serialization, search escaping and limits, entity page content, the query-form guard, truncation and error mapping.
- A test that fails if any scanned file still contains `example.org`.
- Final check against the real Fuseki: curl with each `Accept` header, the nine examples through `/api/query`, and a headless-browser screenshot of the main pages.
